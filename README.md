## Usage

### Use WebpackFramework in a new project:

In your project's git repository, install and initialize <i>Webpack Framework</i>:
```bash
git submodule add git@github.com:denis-migdal/Webpack-Framework.git ./build/WebpackFramework
./build/WebpackFramework/init.sh
```

You can then complete the informations in the `package.json` file.

💡 As a security measure, your existing files will NOT be overridden. Therefore, you may need to install some of the template files yourself.

⚠ You may need to run `npm install @swc/core`.

### Commands

- `npm run build`: build the project.
- `npm run watch`: re-build the project after each changes.
- `npm run tests`: run unit tests.
- `npm run types`: create the `.d.ts` files for templates and libraries.
- `npm run build-prod`: build the production version of the project.

### Symbols

- `__LOAD_FILE__`: an alias to `require()` used to import raw files.
- `__DEBUG__`: `true` if built in dev mode.
- `__ASSERT__(cond, msg)`: assertion function.

## Project structure

I use the following structure in my projects:
```shell
├─ src         # sources
├─ tests       # tests (Deno)
├─ libs        # external librairies
├─ scripts     # tools
├─ build       # build process
|  └─ cache    # files generated by the build process.
└─ dist        # distributed files
```

My `src` directory is structured as follow:
```shell
src
├─ @exports         # exported public symbols
├─ @contracts       # define contracts and services.
├─ modules          # implements contracts (mainly for MWL).
|  └─ @platform     # browser API, stores, codecs, etc.
├─ models           # entities, data structures, rules.
├─ webui            # used by templates.
|  ├─ widgets       # 
|  ├─ orchestrators # ~ pages controllers
|  ├─ capabilities  # features
|  └─ styles        # styles
├─ pages            # Web pages sources (each index.html is a webpage).
|  ├─ @templates    # Web pages templates.
|  |  └─ @domains   # separate templates per domains.
|  ├─ @assets       # assets (can also be an "assets" subdirectory).
|  └─ @tests        # tests
└─ domains          # separate files by domains (future libs).
```

Directories prefixed by `@` have a "structural" meaning distinct from the current context. For example in the `src/webui/widgets` directory, each subdirectory represents a Widget, except `@core` which contains code used to define/create Widgets.

💡 We prefers ./src/@exports to ./src/libs, as generating TS libs requires emissions of .d.ts files, that still have open issues in TS...
